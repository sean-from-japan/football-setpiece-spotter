# football-setpiece-spotter

タッチライン脇の固定広角カメラで撮ったアマチュアのサッカー映像から、セットプレー（まずコーナーキック）の候補時刻を出すツールです。あわせて、その候補が本物のコーナーキックをどれだけ取りこぼしたかを実測します。

**データセットの追跡データでは動きますが、自前の認識では成立しません。**

大学の試合2ハーフ・96分（コーナー12本）に対し、付属の正解座標を使えば**12本すべてを検出**します。適合率は0.83と1.00、再開時刻とのずれは1秒以内です。

一方、自前で作った座標（パノラマをタイル分割してRF-DETRで検出し、ピッチ座標へ変換）に置き換えると、設定を選んだハーフでは再現率1.00ですが、**未見のハーフでは再現率0.43・適合率0.25**まで落ちます。ペナルティエリアの密集は認識に耐えますが、コーナー旗の前に1人で立つキッカーは耐えません。そして判定規則はその1人に全体重を預けています。

数値と、コーナー1本ごとに測った失敗の内訳、設計をどう変えるべきかは [docs/RESULTS.md](docs/RESULTS.md) に書いてあります。

## なぜサッカー映像のリポジトリをもう1本作るのか

検出→追跡→チーム分類→ホモグラフィ→ポゼッション、という流れはすでに解かれた手順です。Roboflowがライブラリとして公開していますし、公開リポジトリにも同じ構成のものが数え切れないほどあります。それをもう一度組み直すことが目的ではありません。

このツールが答えるのは、アマチュアチームのアナリストが実際に抱えている問いのほうです。

> タッチライン脇のカメラで撮った90分の映像から、すべてのコーナーキックを見つけるために、人間はまだ何分見なければならないのか。そのとき何本のコーナーキックを見落とすのか。

したがって主要な数値は**再現率・候補数・確認に要する時間**であり、枠を描いたデモ動画ではありません。教師データは検出器を書く前に作ります。評価を回さずに検出器を変更した場合、それは効果が確認されていない変更として扱います。

## 現時点で動くもの

```console
$ setpiece info data/raw/match.mp4
file:       data/raw/match.mp4
resolution: 3840x2160  (8.3 MP)
codec:      hevc
frame rate: 29.970 fps
duration:   01:30:00  (5400.0s)
frames:     161,838

coarse pass at 2 fps: 10,800 frames (6.7% of the file)
coarse pass at 4 fps: 21,600 frames (13.3% of the file)
```

```console
$ setpiece template > data/labels/match.csv   # 出力したCSVに手作業でラベルを付けます
$ setpiece evaluate data/labels/match.csv data/output/candidates.csv --video data/raw/match.mp4
event:      all
tolerance:  +/-15s
labelled:   14
candidates: 22
...
```

- `setpiece info` — 映像ファイルの実態と、粗い間引き走査にかかる規模を表示します。市販カメラが書き出すコンテナで実際に起きること（フレーム数が入っていない、ストリーム側に長さが入っていない、フレームレートが可変）に対応しています。
- `setpiece template` — 使える語彙が入った空の教師データファイルを出力します。
- `setpiece evaluate` — 候補を教師データと突き合わせます。再現率、適合率、時刻ずれの中央値、見落とした事象の一覧、そして候補数から逆算した確認時間を出します。
- `setpiece import-gsr` — SoccerTrack v2 の2.7 GBの状態注釈をストリーミングで読み、中にある159万件の選手座標を4.4 MBのgzip圧縮CSVとして書き出します。
- `setpiece corners` — その選手座標からコーナー候補を出します。ボールは使いません。公開されているボール軌跡は追跡できているフレームが3分の1しかなく、それ以外はピッチ矩形の角にクランプされるため、コーナー旗の位置に実在しないボールが現れるからです。

ここまでは標準ライブラリと `ffprobe` だけで動きます。モデルもGPUもネットワークも使いません。

残る2つのコマンドは、座標を読む側ではなく作る側です。この2つだけは `detect` エクストラが必要です。

- `setpiece detect` — パノラマをタイルに分割してRF-DETRを走らせ、サンプリングしたフレームごとに、検出した人物を1行ずつ書き出します。タイルの分割数を引数にしているのは、それが処理速度ではなく検出器に何が見えるかを左右するからです（[docs/DECISIONS.md](docs/DECISIONS.md) のD7）。
- `setpiece map-detections` — ピクセル単位の矩形をメートル単位の座標に変換します。既知の座標に対して変換式を当てはめ、当てはめの結果ピッチの外に出た座標は捨てます。

`setpiece detect | map-detections | corners | evaluate` が全体の流れで、冒頭に書いた認識込みの数値はこの流れで出したものです。

## まだ無いもの

追跡とチーム分類です。検出結果はフレーム間で対応づけていないので、ツールから見えているのは同じ22人が動いている様子ではなく、その瞬間ごとの人の集まりです。ペナルティエリアにいる人数を数えるにはこれで足りますが、個人を区別する処理には足りません。

どちらも、同じ教師データに対する `setpiece evaluate` の結果を伴わない形では入れません。認識によって失われる分を、言い訳ではなく数字として残すためです。決めたことと理由は [docs/DECISIONS.md](docs/DECISIONS.md) に書いてあります。既定の検出器をAGPLのYOLOではなくRF-DETR（Apache-2.0）にした理由もそこにあります。

映像は決まりました。開発と評価には **SoccerTrack v2**（大学の10試合・約900分・BePro固定パノラマ4K・CC BY 4.0）を使い、プロの映像との対照には Simula の Alfheim パノラマを使います。ただしコーナーキックは同データセットの12種の事象ラベルに含まれていないので、教師データは引き続き手作業で作ります。詳細は [docs/FOOTAGE.md](docs/FOOTAGE.md) と [docs/LABELLING.md](docs/LABELLING.md) をご覧ください。

## インストール

```bash
python -m pip install .              # 評価部分のみ
python -m pip install '.[detect]'    # 検出器とピッチ座標変換を追加します
```

Python 3.9以降とFFmpeg（`brew install ffmpeg`）が必要です。

## データの扱い

映像・切り出した静止画・ラベル・モデルの重みは、このリポジトリには置きません。コミットされた場合はCIが落ちます。詳細は [docs/DATA_POLICY.md](docs/DATA_POLICY.md) をご覧ください。

## テスト

```bash
python -m unittest discover -s tests -t . -v
```

ネットワーク・GPU・映像ファイルのいずれも必要ありません。
